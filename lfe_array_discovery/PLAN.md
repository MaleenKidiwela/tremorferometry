# lfe_array_discovery — Washington (then Oregon) LFE families from the public temporary arrays, extended to 2026 on the permanent network
Draft v0, 2026-09-20 (Fable, for Merlin refinement). User request: "use the temporary stations to locate the families ourselves and use our network to extend them, like the northern families."

## 0. Why this exists
Every published Cascadia LFE family set (Bostock 2012/2015, Royer & Bostock 2014, Chestler & Creager 2017, Thomas & Bostock 2015, Plourde 2015) was discovered on a temporary dense array and only then carried to permanent stations. P3D/P4 (lfe_picker) showed the permanent network alone cannot discover families (no seed rule selects LFEs; 6–10 usable Puget sites). The Washington and Oregon family catalogs are not public (Royer & Bostock 2014, Thomas & Bostock 2015, Chestler 2017; no author contact allowed) — but the array WAVEFORMS are public at EarthScope (FDSN station query 2026-09-20, `lfe_picker/NOTES.md`; memory `cascadia-temporary-arrays-earthscope`).

## 2. Goal and deliverables
G1 A located, gated Washington LFE family catalog (Olympic Peninsula 47.4–48.3 N first; Puget/S. Washington 46.2–47.4 N second) discovered on arrays + permanent stations in the 2007–2011 ETS windows.
G2 Templates registered on PB/UW permanent stations from the array-era stacks; per-family registration verdict.
G3 Continuous extension 2007→2026 on the permanent stations with the frozen chain (20 Hz, 1–8 Hz, FA-only tiers per epoch, HF veto, completeness + realness as in lfe_extension v1.1).
G4 Oregon (COLZA/FACES/PB, 2009 ETS) as a second, thinner pass if G1 works.

## 3. Discovery arms (all on the same array-era data; family = converged stack with a location)
A. Network autocorrelation (Bostock 2012 / Brown 2008): per-hour autocorrelation on the quiet array+PB sites, cluster the coherent window pairs, seed templates → matched-filter growth (lfe_picker `v_engine`) → two iterated stacks. The proven method on this data.
B. LFEDetect (SeisBench weights) → PyOcto association → per-event locations → space-time clustering → stacks (Thomas/Lin route). Public, cross-region trained.
C. Our P1/P2 picker as a cross-check arm only.
Lessons carried from P4-0b: energy-z seeds do not select LFEs (2–7 %) → seeds must come from coherence (A) or a detector (B), never energy; purity truth must be cluster-based (families 0.1–1.6 km apart); growth-threshold floors must be exercised by the FA rule; per-day availability, never intersected.

## 4. Location
Stack-and-pick S (and P where visible) at array + PB stations; Crosson 1-D + station corrections from intraslab earthquakes (lfe_extension `a5_eq_corrections.py` recipe); shuffled-pick and synthetic-floor controls; energy back-projection as first guess; relative relocation later. Target: ≤3 km horizontal, ≤5 km depth for families with ≥15 stations.

## 5. Gates (pre-registered, as lfe_picker Gates 0–3)
Withheld permanent stations never used in discovery (e.g. 3 PB + 2 UW per sub-region); Gate 0 class/HF/earthquake veto + distinctness; Gate 1 coherence at withheld stations vs random-time and moveout-shuffled nulls; Gate 2 location with controls; Gate 3 tremor timing (local vs distant); N-shift whole-chain null ≥3 realisations. One ETS window sealed (2011-08) for a final re-fire test. Descriptive comparison to Chestler's 69 derived coordinates.

## 6. Registration and extension
For each gated family: stack PB/UW at array-era detection times → registration verdict per station (S excess vs nulls) → 12-s templates in the frozen npz format → FA-only thresholds per network epoch → production run 2007→2026 → completeness model, realness score, family tables and cumulative plots as in lfe_extension.

## 7. Data and compute (rough)
Discovery: 5 windows × ~35 d × ~150–250 stations ≈ 35k station-days ≈ 0.7 TB raw + 20-Hz cache; ~3 h FDSN at 4 station-days/s. Extension: ~25 permanent stations × 2007–2026 ≈ 180k station-days ≈ 3.6 TB raw (71 TB free); ~12 h FDSN. GPU: autocorrelation per hour over ~50 sites × 175 days; LFEDetect over 35k station-days; growth passes as in P4-0b (~800 template-station-days/s).
Download strategy (user requirement): start Olympic 2010-08 (densest: XG 115 + XU 19 + PB 19) first and begin discovery on it while the other windows download; extension download runs in the background from day one for the PB/UW roster.

## 8. Governance
Pre-registration + hashes before every scoring pass; sealed window; withheld stations; no author contact; Opus agents launch shell queues and exit; Fable orchestrates only.
