# 2026-06-18 Notes — B011 P(LFE)≥0.5 families: how we reached "274 real LFE templates"

Question answered: *of the 314 B011 P(LFE)≥0.5 family templates, how many are real LFEs?*
**Answer: 274 (picker-classified LFE), 35 earthquake-multiplets, 5 in-tremor-noise; 126 high-confidence (P≥0.7).**

Full LFE-feature program lives in `lfe_features/` (PLAN.md / RESULTS.md / DECISIONS.md). This note is just the
exact chain that produced the 274.

## The categorizer (what "real LFE" means here)
The **picker** = the feature classifier built in R1–R9 (`lfe_features/`): spectral slope / low centroid /
2–8 Hz band concentration / HF-depletion + **3-component polarization** (hv_ratio, rectilinearity, planarity) +
emergent onset. LFE-vs-noise AUC ~0.98, LFE-vs-EQ and LFE-vs-blast ~0.97. Saved 4-class model
`lfe_features/models/tremor_picker_b011.joblib` (classes LFE / EQ / BLAST / TNOISE).
- **Polarization is INSIDE the picker** — not a separate filter (corrected a mis-statement mid-session).
- **Lin-catalog coincidence was only an EXTERNAL validation cross-check, NOT the categorizer** — it's
  coverage-limited (no Olympic side), so the picker (works everywhere) is what we categorize by.
- Known weak spot (a finding, not a bug): LFE-vs-in-tremor-ambient = 0.81 (single-station "emergent-noise wall").

## The chain (step → script → params → result)
1. **Candidates** = PNSN tremor-window envelope-peak detections at B011 (`data/b011_pnsn_candidates_100km.parquet`),
   restricted to **2010–2013** → **415,313** candidate detections.
2. **Score candidates with the picker** (`lfe_features/score_candidates.py`) → P(LFE) per candidate.
   Filter **P(LFE)≥0.5** → **82,582** candidates (`data/b011_cand_p50.parquet`). [for ref: ≥0.4→133k, ≥0.7→26k]
3. **Cluster into families** (`scripts/discover_gpu.py`, fs=100, cc≥0.8 complete-linkage, ≥3 members & ≥3 years,
   max-bin 2000) → **314 families / seed templates** (`data/b011_disc_p50.{npz,summary.csv,members.parquet}`).
   [P≥0.7 gave 52; P≥0.4 gave 610.]  Members are only the seed cluster: **3–9 each (median 3, 1,129 total)** —
   NOT densified.
4. **Pre-densify shape screen** (family-CWI predictor: centroid>4.3 Hz & kurt>4 → spiky/BAD): **0/314 flagged**;
   template centroid median **3.09 Hz** → all low-frequency, none earthquake/blast-spiky-shaped. (This screen only
   catches the SPIKY class; the hard in-tremor-noise contaminant is low-freq and passes it — so "passes screen"
   ≠ "clean".)
5. **Categorize each family with the picker** (`lfe_features/score_family_stacks_picker.py`): for each family,
   coherently stack its 3–9 member detections in **3 components** (Z+EH1+EH2, per-detection amplitude-normalized
   to preserve H/V), extract the features, run `tremor_picker_b011.joblib`. → `data/family_picker_p50.csv`.

## Result (step 5)
| picker class | count |
|---|---|
| **LFE (real)** | **274** |
| EQ (repeating-earthquake multiplet) | 35 |
| in-tremor noise (TNOISE) | 5 |
| blast | 0 |

Family-stack P(LFE): median **0.65**; **≥0.5: 237 · ≥0.7: 126 · ≥0.9: 19**.
→ **274/314 (87%) real LFE; 40 contaminants (35 EQ multiplets + 5 noise); 126 high-confidence.**

## Caveats (don't over-trust the borderline tail)
- The categorization stacks only the **3–9 seed members** per family → noisy for small families → borderline
  (P 0.5–0.7) calls are not final. The **densify now running** (`mf_b011p50_`, all 314, full 2007–2017 record,
  `logs/densify_b011p50.log`) gives thousands of detections/family → cleaner stacks for a sharper re-categorization,
  and the detection histories for dv/v.
- Candidate P≥0.5 prefilter compresses the family-MEAN P(LFE) (members all ≥0.5); the **family-STACK** score used
  here is the uncompressed per-family verdict (why we stacked rather than averaged member P).
- Scope: B011 only; candidates 2010–2013.
- The picker DID catch 35 repeating-earthquake families — exactly the EQ-multiplet contamination that the old
  Z-only/2-s discovery would have admitted as spurious "LFE families".
