# 2026-06-13 Notes — LFE detection method review + Lin-as-ground-truth pivot

## 1. Methodological review: is envelope-peak detection the right way to pick LFEs?
User-driven interrogation of the discovery method. Verdict: **envelope-peak detection is a
defensible cheap SEEDING/bootstrap heuristic, NOT a proper LFE picker.**
- LFEs are emergent / low-f / low-SNR; envelope-peak (bandpass 2-8Hz -> Hilbert env -> peaks
  >3x background, `discover_nllb_pnsn_driven.py` stage 1) is an IMPULSIVE-burst detector -> same
  anti-LFE bias the project already found downstream (SNR/cc traps).
- Costs: (a) discovery INCOMPLETENESS (purely-emergent families never trip a 3x peak -> never seeded),
  (b) over-seeds impulsive contaminants, (c) NO depth/interface or network constraint -> happily clusters
  repeating shallow microquake multiplets into "families" (= root of the T2a site-carrier problem).
- Saving grace: it's a bootstrap — a few impulsive members build a template, then matched-filter densify
  recovers the emergent rest. Bias is in WHICH families discovered, not each family's completeness.
- Field standard (how people actually catalog LFEs): network matched-filter w/ iterative template refine
  (Shelly 2007/2017), template-free network autocorrelation (Brown 2008). Tremor catalogs (PNSN/Wech-Creager)
  use ENVELOPE cross-correlation for LOCATION, not event picking — we borrowed a tremor tool for an event task.
  The field's SNR + noise rejection come from NETWORK summation; we're single-station (the dropped 2-sta
  protection, §7 of 06-11). => "do it like the field" == Phase C (re-add the network).

## 2. Lin (2023) catalog — what it actually is
DL-based LFE catalog, southern Vancouver Island (Seismica; Zenodo 10.5281/ZENODO.10016020), expanded from
the Bostock 2012/2015 lineage. `data/raw_lfe/lin2023_lfe.csv`: 1,058,114 detections, 2005-01-01..2017-02-21,
lat 48.07-49.32, lon -124.57..-122.94, depth median ~30km (interface). Columns:
starttime, OT(origin), lon, lat, depth, residual(loc fit), dt(OT-start), N(#stations 3-14, median 4).
NOT in it: waveforms (we extract ourselves), family labels (we grid-bin), per-detection station list, magnitude.

## 3. THE PIVOT — use Lin as a labeled LFE training set (supervised Phase C)
Idea (user): train ML to detect LFEs and reject non-LFE contaminants using Lin as positive labels.
- Positives: Lin LFE windows; curate clean set via N>=6, residual<~0.8s, depth 25-45km.
- Hard negatives (we already have): reversed-template fakes, fingerprint CULTURAL/BLAST/NATURAL classes,
  FAIL families, regional ANSS EQs.
- Two tasks: (A) CLEAN existing densified lists (score mf_* dets, re-stack) = cheap/high-value;
  (B) detect from scratch = full Phase C.
- Risks: (1) domain shift VI-broadband -> WA-borehole; (2) emergent-noise wall — single-station spectral
  features (centroid/kurtosis) already FAIL to catch the emergent noise-ACF class; the discriminating info
  is multi-station MOVEOUT, not one station's spectrum. So Z-only single-station ML may hit the same ceiling.

## 6. Pitfall logged (cost a rerun)
pandas 2.x `pd.to_datetime(...)` returns **datetime64[us]** here; `.astype('int64')` gives MICROSECONDS, not
ns -> dividing by 1e9 mis-scales time by 1000x (Lin span printed as "1970"). Fix: force ns first:
`pd.to_datetime(s, utc=True).values.astype('datetime64[ns]').astype('int64')/1e9`.

## 8. LFE FEATURE-FINGERPRINT EXPLORATION (new workspace `lfe_features/`, full docs there)
Goal (user-set): credible LFE features/fingerprints -> toward an EQTransformer-style probabilistic LFE picker.
Lin-coincidence test (B011 dets vs Lin OT) was CONFOUNDED (location-bin mismatch + noise dilution + episode
smear) -> pivoted to feature-space fingerprinting. Built lfe_features/ (PLAN.md, RESULTS.md + 7 scripts).

**RESULT 1 (solid): credible LFE fingerprint.** Trained on Lin LFEs (LIN, N>=6/res<1.2/<=35km) vs random
windows (RAND), 40s windows, hand-crafted spectral+envelope+3-comp-polarization features. LIN-vs-RAND
CV-AUC 0.95-0.98 at BOTH CN.PGC (broadband) and PB.B011 (borehole). **SNR-INDEPENDENT** (AUC unchanged
dropping all amplitude features; snr Cohen's d ~0) -> it's waveform CHARACTER not loudness. Fingerprint:
steep neg spectral slope, high polarization, energy in 2-8Hz, HF-depleted.

**RESULT 2 (verified after catching 3 of my own artifacts): B011 trust-families are coherent low-frequency
HF-depleted repeaters, spectrally LFE-CONSISTENT** (not noise, not impulsive-EQ). The journey:
per-window P(LFE)~0.1 (noise-diluted lists, expected) -> naive stack P 0.48 -> alignment-robust stack P 0.165
(looked "not LFE") -> BUT raw spectra show family stacks are the MOST low-freq/HF-depleted (centroid 4Hz,
bf_2_4=0.79, hf_ratio 0.05 vs LIN 7.2/0.38/0.42 vs RAND 8.7/0.23/0.92). The 0.165 was a CLASSIFIER
EXTRAPOLATION artifact (families beyond the LIN cloud on the low-freq side) + my LIN stack reference was
itself degraded by anchor-jitter. figures/spectra_compare_b011.png is the key evidence.

**LESSONS:** (a) align positives precisely BEFORE stacking (anchor-jitter smears + inflates HF -> degrades
the LFE reference); (b) inspect RAW feature distributions, never trust a classifier P at the cloud edge
(extrapolation); (c) per-window can't judge a family (90/day noise dilution) -> use coherent stacks.
