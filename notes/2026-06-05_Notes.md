## PGC 2013-2015 dv/v "sudden drop" = GLITCH ARTIFACT (diagnosed + fixed)

User flagged a sudden dv/v drop 2013-2015 at PGC. Chased it down:
- **Cause:** PGC 2013-2014 waveforms are impulsive-glitch contaminated + fragmented (telemetry; ~55
  traces/day vs 1, but only ~0.4% real gaps). Matched filter false-triggers >2000/fam-day → densify QC
  (`--qc-median-count 2000`) drops ~90% of days → only ~40 glitchy survivors/yr → biased deep low (−0.074%).
  An artifact, NOT velocity. (It survived per-era AND all-time refs because both share the bad data.)
- **Diagnostics:** days-with-detections/yr (2013=42, 2014=38, vs ~350); traces/day; outlier-sample fraction
  (5-100x clean years). Figures: smoke_pgc_2013_glitch_diagnosis.png, _despike_test.png.
- **Fix:** added **`--despike-mad K`** (winsorize beyond K·MAD/day) to BOTH `densify_gnw_gpu.py` and
  `build_long_window_resp.py`. Re-densified 2013-2014 with `--despike-mad 8` → 42→365 / 38→364 days,
  0 QC-dropped. Re-stacked all PGC (`long_window_daily_PGC_despike.npz`), re-ran all-time 1-3s dv/v.
- **Result:** 2013H2-2014H1 median −0.074% (33 days) → **−0.020% (365 days)**; drop gone, continuous with
  neighbors. Figs: smoke_dvv_PGC_alltime_1to3_despike.png, smoke_dvv_PGC_despike_BEFORE_AFTER.png.
  Originals preserved in data/backup_pgc_glitchy/. See memory [[glitch-days-false-dvv-drop]].
