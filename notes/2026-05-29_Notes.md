# 05-29-26 Notes — full coda dv/v workflow (backfill → dv/v)

End-to-end, reusable per-station workflow for NLLB-style LFE-coda dv/v, as run this
session on **UW.HDW** (worked example) and **UW.GNW**. Built for the 32-CPU + 1× L40S pod.
All scripts are generic (pass `--station`); this is the runbook for adding any station.

Pipeline:  **backfill → PNSN catalog → station box → discover (stage1+GPU stage2) →
coverage-select → densify (GPU MF) → daily stacks → coda dv/v → metadata QC.**

---

## 0. Waveform backfill (download)
`scripts/download_hdw.py` — FDSN bulk pull of one station's vertical channel, daily files
into `data/waveforms/<NET>.<STA>/<year>/<jday>.mseed`. Threaded (8 workers), resumable,
picks preferred vertical channel (EHZ>HHZ>BHZ>SHZ). HDW: 1995–2026, 11,281 files, 73 GB.
- Generic: copy/parametrize for any NET.STA. Keep ALL data (not just tremor days) — the
  matched filter runs on every day.

## 1. PNSN tremor catalog  ⚠ GOTCHA
The catalog drives candidate detection. **`catalogs/pnsn_tremor_2014-2026.csv` is
download-cut at lat 47.5°N** (fetched with `00b_fetch_pnsn_tremor.py --bbox 47.5 ...`) →
zero tremor south of 47.5, which starves stations near/south of that line.
- **USE THE MASTER:** `catalogs/pnsn_tremor_cascadia_full.csv` — 748k rows, lat 39.5–50.9,
  2010–2026 (full Cascadia). Source: tremorapi.pnsn.org (`scripts/00b_fetch_pnsn_tremor.py`).
- Tremor catalog only starts ~2010 → families are 2010+ LFEs (still matched-filtered across
  the full waveform record in densify).

## 2. Station-centered box (per user)
Center the discovery bbox on the station, choose ±km (don't use arbitrary geographic boxes).
HDW (47.649, -123.053), ±100 km N/S+E/W → bbox `46.748 48.550 -124.390 -121.716`.
- Preview: `scripts/plot_station_box.py --station HDW --station-lat .. --station-lon .. --ns-km 100 --ew-km 100`
- The tremor band has a **downdip (eastern) edge** — families terminate where the slab drops
  below the ETS depth window (`scripts/plot_downdip_edge.py`). That eastern blank is real, not missing data.

## 3a. Discovery STAGE 1 — candidate detection
`scripts/discover_nllb_pnsn_driven.py --candidates-only` — envelope-peak detections at the
station inside every PNSN tremor window. Now uses `_load_day_poly` (resample_poly) + a
`--candidates-only` flag.
```
python scripts/discover_nllb_pnsn_driven.py --station HDW \
  --pnsn catalogs/pnsn_tremor_cascadia_full.csv \
  --bbox 46.748 48.550 -124.390 -121.716 \
  --candidates-out data/hdw_pnsn_candidates_100km.parquet --candidates-only --workers 16
```
⚠ MEMORY: at 24 workers with obspy FFT-resample this hit anon 99 G (near-OOM). The
`resample_poly` loader + 16 workers → anon **4 G**, 1543 days in ~95 s. HDW: 1.72 M candidates.

## 3b. Discovery STAGE 2 — GPU clustering  (the big speedup)
`scripts/discover_gpu.py` — replaces the slow/OOM CPU clustering. Three wins, validated
bit-equivalent (zero cluster-flips at cc≥0.8):
1. **load-each-day-once** (group cuts by calendar day; ~11k loads not ~100k)
2. **resample_poly** not obspy FFT-resample
3. **GPU all-pairs max-shifted CC** (`src/tremorferometry/repeater_gpu.py`): 11.6 s → 0.06 s
   per 2000-window bin, 197×, max|Δ|=1.8e-7 vs CPU.
Single GPU process; CPU workers only cut waveforms (KB) → no N²-per-worker blowup → full
2000-cap, no OOM.
```
python scripts/discover_gpu.py --station HDW \
  --candidates data/hdw_pnsn_candidates_100km.parquet \
  --out data/hdw_pnsn_families_100km.npz --max-bin-candidates 2000 --workers 24
```
HDW: **29,721 families in 89 s at anon 2 G** (CPU path was ~100 min / 54 G / 50-cap).
⚠ It writes the **`snr` column** (template env-peak / pre-pulse-RMS, pre=T[:34]) that the
committed discover script silently stopped writing — coverage selection / map need it.
Output: `*.npz` (templates) + `.summary.csv` (family_id,n_members,n_years,first/last_year,lat,lon,snr) + `.members.parquet`.

## 4. Coverage-balanced family selection
`scripts/select_coverage_families.py` — bin by (azimuth sector × distance ring) from the
station, keep top-K per cell by SNR with an SNR floor. Avoids 100s of redundant clustered
patches; fills azimuth/distance evenly; loosens to the floor only where a cell is empty.
```
python scripts/select_coverage_families.py --summary data/hdw_pnsn_families_100km.summary.csv \
  --station-lat 47.649 --station-lon -123.053 --min-snr 10 \
  --az-sectors 12 --dist-rings "0,20,40,65,100" --k 2 \
  --out data/hdw_coverage_selection_100km.summary.csv --out-fig <fig>
```
HDW: 96 SNR≥10 → 37 selected (+5 southern-tail by hand) = 42; 10/12 az sectors, all rings.
Maps: `scripts/plot_family_map.py` (SNR≥X family map), `scripts/plot_candidate_map.py`
(raw candidate density; `--extent` to show the full box).

## 5. Densify — GPU matched filter
`scripts/densify_gnw_gpu.py` — runs the selected templates across the full waveform record.
GPU rfft template×data + GPU sliding-norm + cc>1 fix + threshold + sparse extraction; CPU pool
preprocesses (resample_poly). ~180× CPU. Per-year chunks, resumes by skipping existing
`<prefix>YYYY.csv`. QC: drops a day if median count>2000 or median cc>0.96; **top-N=100 cap**
per (family,day); **`--max-raw-det 3000000` glitch-day guard** (skip pathological days BEFORE
the O(N) dedup — speeds glitchy analog-era years ~5×).
```
python scripts/densify_gnw_gpu.py --templates-npz data/hdw_pnsn_families_100km.npz \
  --summary-csv data/hdw_densify_set.summary.csv --min-snr 0 \
  --network UW --station HDW --out-prefix mf_hdw_ --workers 20 --top-n 100 --max-raw-det 3000000
```
Selection = summary∩npz filtered by `--min-snr`. HDW (42 fam, 2010–2026): ~24 days/s, GPU 84%,
anon ~15 G. (For a long Nisqually baseline, run from 1995 — glitch guard handles the old data.)

## 6. Daily stacks
`scripts/build_long_window_resp.py --no-deconv` — for each (family, day), cut a 13 s long
window (−3..+10 s, 520 samp @ 40 Hz) around each detection and stack (average). **spawn** workers
(no COW; the old fork stacker ballooned to ~135 G). `--no-deconv` = resample_poly + bandpass
(the resample_poly fix kills the obspy dv/v drift; deconv only matters cross-era).
```
python scripts/build_long_window_resp.py --mf-csv data/mf_hdw_all.csv --network UW --station HDW \
  --no-deconv --workers 16 --out data/long_window_daily_HDW.npz
```
Output npz keys: `stacks (n,520) patches(n) dates(n) n_det(n) t(520) fs`. (concat year CSVs → mf_*_all.csv first.)
- **REUSE, don't re-stack:** stacks are mergeable across runs (same 520-sample format).
  `scripts/merge_stacks.py` concatenates several npz and dedupes (patch,date), keeping max-n_det.
  GNW: merged 53+22+28 family stacks (767k → 714k rows after dedup) **without** re-stacking the 75.
  ⚠ **CONSISTENCY: only merge stacks built with the SAME resampler.** The OLD GNW base
  `long_window_daily_GNW.npz` was built by `build_long_window_daily_all51.py` which uses
  **obspy FFT resample → contaminated by the spurious obspy dv/v drift**. `build_long_window_resp.py`
  uses `resample_poly` (clean). Merging the obspy `GNW.npz` (53) with resample_poly circle/gap
  stacks gave an INCONSISTENT no-deconv merged dv/v (53 main drift-contaminated). The clean base is
  `long_window_daily_GNW_resp.npz` (resample_poly + deconv). Response-removed merged build = stack
  circle+gap with deconv (default = resample_poly→deconv, `--inv data/UW.GNW.response.xml`) → merge
  with `GNW_resp.npz` → per-era dv/v (era-bounds `2010-09-10,2019-05-07`). Note: response removal
  does NOT flatten cross-era steps — per-era referencing is still required; deconv just makes the
  base consistent + clean.

## 7. Coda dv/v
`scripts/dvv_coda_parallel.py` (all-time-mean ref) and `scripts/dvv_coda_perera.py` (per-era ref).
Stretch each day's coda (default 1–4 s here) against the family reference; cross-patch 60-d median.
```
python scripts/dvv_coda_perera.py --npz data/long_window_daily_GNW_merged.npz --window 1.0 4.0 \
  --station GNW --era-bounds "2010-12-01,2019-05-07" \
  --out-csv <csv> --out-fig <fig> --workers 24
```

## 8. Metadata QC  ⚠ ALWAYS DO THIS
Sensor/sample-rate changes inject apparent dv/v steps. Two safeguards:
- **Per-era referencing** at the rate/sensor-change dates (each instrument epoch referenced
  to its own mean). Get the dates from FDSN, NOT guesses.
- **Overlay all metadata changes** on the dv/v: `scripts/plot_dvv_metadata.py --station <STA>`
  (fetches FDSN channel epochs, flags sensor/rate changes red, response epochs grey).
Rule of thumb: distrust dv/v jumps that coincide with a red line; trust the rest.

Verifying "real": (1) not coincident with a metadata change (survives per-era), (2) coherent
across many patches (e.g. 90% of patches), (3) ideally appears at neighbouring stations.

## Key gotchas (carry forward)
- PNSN catalog 47.5°N cut → use `pnsn_tremor_cascadia_full.csv`; center box on station.
- obspy FFT-resample = recurring OOM + dv/v drift → **resample_poly everywhere**.
- Sensor/rate swaps fake dv/v steps → per-era + metadata overlay (HDW EHZ→HHZ, GNW 50→40→100).
- discover_gpu.py must write the `snr` column (committed discover script dropped it).
- Reuse daily stacks (merge_stacks.py); don't re-stack already-done families.
- Glitch-day guard (`--max-raw-det`) for slow analog-era densify.
- Monitor loops: grep with the bracket trick (`[d]ensify…`) or they self-match and hang.
- Pod cap 32 CPU; keep total workers ≤30. Always run a memory watchdog (anon > ~120 G = kill).
