## R10 — wired into REAL GPU discovery (the "better seeds?" proof), B011 2010-2013
score_candidates.py → P(LFE) on 415k candidates → baseline (all) vs filtered (P≥0.4, kept 32%) parquets →
discover_gpu (fs=100, cc≥0.8, ≥3 members, min-years=3, max-bin 2000) on each → classify families by ground
truth coincidence (compare_discovery.py / fam_level_filter.py).
- Baseline 4875 families (1254 Lin-confirmed, purity 25.7%); Filtered 610 (235 LFE, 38.5%).
- **Finding A: filter at the FAMILY level, not candidate level.** Candidate-level fragments families (kept
  only 19% of LFE families). Family-level (cluster → score family by mean member P(LFE)): thr 0.2 keeps 72%
  LFE / removes 46% contaminants; thr 0.3 keeps 49% / removes 69%. Use as a gentle quality gate.
- **Finding B: B011's contamination is NOT EQ/blast** (only 5 EQ, 0 blast families of 4875) — it's the hard
  in-tremor/uncatalogued class. So the picker's 0.97 EQ/blast strength barely bites here; it would help MUCH
  more at EQ/blast-contaminated stations (anthropogenic B018/B033/CPW/GNW; natural-seismicity B935/B017/B022).
  Also Lin-confirmation UNDERESTIMATES purity (many UNK families = real LFEs outside Lin's catalog at B011's edge).
- Verdict on "does it make better seeds?": YES, best as a family-level filter that removes EQ/blast multiplet
  seeds (the original contamination) + trims low-P families; leverage is STATION-DEPENDENT.

## Design Q&A (user)
- "Tremor-windowed pick→densify vs continuous-pick→cluster?" → **tremor-windowed → densify is better** for the
  primary pipeline: densify already gives continuous per-family coverage regardless of seeding, tremor-windows
  give a high LFE base-rate (tractable precision) + location prior, and continuous's completeness edge is
  marginal because LFE families ARE tremor. Continuous picker = complement (completeness top-up + QC).
- "Using the autoencoder?" → not yet; hand-crafted features drive the picker. AE (R6) was the unsupervised
  validation (latent AUC 0.965). Natural use = concat AE latent to attack the 0.81 in-tremor-noise residual
  (needs an AE retrain incl. TNOISE/BLAST — only latents were saved, not weights).

## R11 — template-length test (CORRECTION to my "longer would help" claim)
Tested longer/varied-cc templates on B011 baseline candidates: 2s/cc0.8 = 4875 fam 25.7% purity;
4s/cc0.8 = 37 fam 8% (collapses, selects coherent contaminants); 4s/cc0.65 = 2973 fam 24.3%; 6s/cc0.65 =
254 fam 17.7%. **No length beats 2s for CLUSTERING purity.** Why: N_eff/longer-template helps matched-filter
DETECTION (coherent samples), but for CLUSTERING the added samples are LFE CODA which DECORRELATES between
occurrences -> cc>=0.8 over long window unmeetable for emergent LFEs (families collapse); survivors are
coherent-impulsive contaminants ("high-cc selects against LFEs" trap). So ~2s ≈ the coherent duration of an
LFE waveform; 2s is fine for clustering. Real lever for cleaner seeds = the PICKER, not template length.
UNTESTED: 3-component templates (independent coherent info on horizontals, no coda problem) — needs
discover_gpu Z-only->3-comp code change.
