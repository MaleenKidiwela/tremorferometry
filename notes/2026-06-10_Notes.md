## 1. Step-injection benchmark VERDICT (differential design, B928, 12 patches)
`scripts/bench_step_recovery.py` — inject known stretch step into real daily stacks, run estimators on
injected AND control arms, subtract (natural variability cancels). Two step sizes: 0.066% (sub-noise)
and 0.435% (earthquake-size) as-read. Figures `figures/bench_step{,big}_B928.png`, metrics in `data/`.

| finding | number |
|---|---|
| Production (30-cal-day boxcar + SVD-Wiener) step response | clean ~24-d ramp STARTING at event |
| SVD-Wiener backward leakage | **nil** (−2..−4% of step) — denoiser does NOT fake precursors or move timing |
| SVD-Wiener amplitude shrink | mild (0.94–0.96 recovery vs 0.96–0.98 without) |
| TV denoise backward leakage | **27–34% of step appears BEFORE the event** → DISQUALIFIED for event timing |
| roll10 | rise 8 d but mixture artifacts (spurious dips in transition) + 1.6× noise |
| daily (no smoothing) | full amplitude in 1–6 d; noise 0.26% — resolution is there, it's a NOISE problem |
| causal Kalman (jump-gated) | most stable of ALL (0.043–0.045% vs prod 0.071%), zero leak, but jump gate mistuned (rise 56–105 d) |

**Conclusion:** the user's worry was half right — smearing is real (the BOXCAR's ~24-d ramp), but the
SVD-Wiener denoiser is innocent on timing/leakage. The path to better temporal resolution is NOT a
better smoother but a lower-noise per-day MEASUREMENT layer → pairwise doublet-matrix estimator
(Opus agent prototyping `scripts/dvv_pairwise.py`) + a retuned causal jump-Kalman as the state layer.
TV-style (ℓ1) smoothers are precursor-fakers; never use for earthquake claims.

## 2. ⚠⚠ ABSOLUTE dv/v SCALE: window-dependent under-read, fixed by origin anchoring
Calibration probes (B928): `stretch_dvv` stretches about SAMPLE 0 (t[0]=−3 s), physical stretch is about
the LFE origin (t=0). Measured/injected: **1–3 s = 0.30×, 2–4 s = 0.44×, 3–5 s = 0.56×** (≈ lapse-ratio
prediction; 1–3 s extra-diluted by the pinned S pulse). Two consequences:
1. ALL absolute dv/v numbers are under-read (2–4 s: true values ~2.3× larger; ETS bound 0.019%→~0.044% true).
   Temporal structure / cross-station patterns unaffected (uniform per window).
2. **The multi-window joint inversion mixed windows with DIFFERENT scales** (same fault signal reads
   ~1.9× stronger in 3–5 s than 1–3 s artifactually) — the across-window common-mode (= the fault field)
   and the window-specific terms (= sites) are both biased. Multi-window products need re-measure+re-inversion.
**FIX implemented:** `dvv_roll30cal.py --origin-anchor` (trim to t≥0, window passed as true lapse) —
recovers 0.97–1.02× in ALL windows. Validating on B928 (`data/daily_dvv_B928_2to4_calT.csv`), then a
coordinated full re-measure (28 stations × 3 windows, suffix `_calT`) ONCE CPU frees. NOTHING deleted —
`_cal` files stay; `_calT` = true-scale generation.

Opus-agent prototype `scripts/dvv_pairwise.py` (staggered-lag doublet graph ≤14 d, cc²-weighted IRLS-Huber,

|---|---|---|---|---|
| prod 30-d boxcar+SVD | **0.071%** | amp 0.94, rise80 **24 d** | amp 0.96, rise80 **25 d** | nil |
| **pairwise doublet** | 0.117–0.130% | amp 0.96, rise80 **12 d** | amp 0.96, **rise50 1 d, rise80 2 d** | nil |

starting at the SAME date in the boxcar. TV remains disqualified (fakes precursors).
