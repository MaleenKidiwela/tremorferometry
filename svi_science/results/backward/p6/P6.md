- **G1 recipe** = `svi_ref_fit.fit_cal` unchanged (HistGradientBoosting max_leaf_nodes 15, min_samples_leaf 200,
  l2 2, lr 0.05, ≤ 300 iterations with early stopping; isotonic `CalibratedClassifierCV`, GroupKFold(3) by day).
  Fit rows = `series == "data"` rows of the 2011 days with role `fit` and of the 2012 days with role `fit` in the
  TEST blocks only (`svi_ref_common.block_role == "fit"`), exactly `bw_gate_g1_score.scored()`. Labels `m_same` (one
  of his events of the same family within ± 2 s) and `m_any` (any family). 5 outer folds grouped by day
  (`default_rng(11)` permutation, as G1) give out-of-fold P for evaluation; the production model is fitted on all
  fit rows; the 5 fold models are kept for the fold spread (`P_same_WAVE_foldsd`). 2013 is never read; 2010 is
  scored once for B0 out of sample (as G1), reported only.
- **Feature set of every model fitted here = WAVE_GEN** = the forward WAVE list minus the per-station `z_<sta>`
  columns and minus `has_LRIV`, `has_SNB` (constant in these sets). **Deviation from G1, decided before fitting:** G1
  kept the per-station z of the set's stations. In the application years stations are missing for long stretches
  (NLLB absent on every day of 2003, VGZ before 2003-02-27, POLARIS sites ending one by one in 2004–2006, PB start-up
  gaps), which the 2011–12 fit rows never show; a tree model sends such missing values down an arbitrary branch.
  The network/site summaries (`site_z_*`, `n_z*`, `dom_top`, `n_sta`, …) carry the same information without that
  problem. The G1 variant with z (`WAVE_Z`) is fitted out of fold beside it on the same rows and reported (dev only).
- **Era model:** fit rows = `series == "data"` rows of the production era run `p5e_2004` on the days of Bostock's
  2004 window (2004-07-02 → 2004-07-27, `truth_episodes.csv`) in the **build** blocks only (`block_role ==
  "insample"`: even 2-h blocks, 60-s block edges excluded). Labels from `bw_gate_common.bostock_all()` 2004 events
  (frozen 2012 offsets, no re-timing; ± 2 s matching is not affected by the whole-second truncation, GATES G2). Same
  learner, folds and WAVE_GEN features. The test blocks of 2004 are never fitted on; they were seen once in G3.
  Caveat known now: the era templates were built on the same build blocks, so the era model's fit rows are the
  templates' own events (in-sample for the templates); the one look on 2003 and 2005-09 is the honest check.
- **KELB gain (choice: EXCLUDE, not correct).** `rel_amp` = Σ_s w_s cc_s √(E3_s / ampref_s) / Σ w is summed inside
  the matched filter; the per-station energy E3_s is not stored, so KELB's term cannot be rescaled after the fact.
  Era candidates on days **before 2003-07-31** (KELB gain 6.17e7) therefore get P from the **era-noamp** model
  (WAVE_GEN without `rel_amp`, same fit rows). All other era days use the era model. Diagnostic (reported, not a
  pass rule): on era days 2003-07-31 → 2004-06-03 (KELB at the 3.07e8 gain, `rel_amp` valid) both models are applied;
  ΣP(noamp) / ΣP(era) for data and control and their out-of-fold AUC on the 2004 build blocks show the size of the
  switch.
- **Which model a candidate gets:** frozen-detector runs `p5f_<Y>`: the set of its date (table above). Ladder runs
  `lad_<OLD>_<date>`: the OLD set's model (B3 = frozen S14 model). P4-2 runs on the 2014–17 E0 quiet days
  (`p4/mf/feat/p4e0_<set>`, used by P7 for station-set invariance): their set's model (S15fix → frozen model). Era runs:
  era / era-noamp. The superseded `p5e_2003` (before KELB) also gets era P (bookkeeping only).
- Every candidate of every run gets P_same and P_any (headline P = P_same, as forward), the fold spread, and, for
  CN4/B1 frozen candidates, also the unrefit frozen forward `WAVE_same` (column `P_same_frozenS15`, comparison only).
- Output: `P/<run>_P.parquet` with `run, date, row, series, fam, t, net_mad, P, P_same, P_any, P_same_foldsd,
  model, net_set` (`row` = 0-based row of `<date>.parquet`, the key of `p4b/sidecar`), and `P_ref` columns as above.
  Model file `models/bw_models.joblib` + `models/MODELS_FROZEN_BW.json` (sha256, features, fit rows), written BEFORE
  the one look and never changed afterwards.

### Calibration check (label-free; before the look)
- Per detector × set × year, on all production days and on between days (> 3 d from every Bostock window): fraction
  of scrambled-control candidates with P > 0.5, with a 2000-draw day bootstrap 95 % interval.
- Forward reference: **3 %** (the SCOPE / G1 bar; forward S15 dev 3.3 %, sealed 2.4 %).
- **"Clearly above 3 %"** = point estimate > 4.5 % (1.5 × 3 %) AND bootstrap 95 % lower bound > 3 %.
- **Outcome map** (my reading of the coordinator brief; no separate Merlin document with this name exists in the repo):
  1. Not clearly above → P as is.
  2. Clearly above for CN4 (B0) or B1 → the rule "refit P per set via the G1 recipe before rates" applies. Here B0/B1
     are never given the frozen S15 model; their P is already the per-set G1-recipe refit (the frozen-S15 P is
     computed beside it only to show the difference). In addition, for that set: (i) rates are reported only as ΣP
     excess (data − control, P7), never as ΣP of data alone; (ii) its single repeats carry `ctl_heavy_set = True`
     in the catalogue; (iii) beside the headline count at P ≥ 0.75, a count at **P\*_set** is reported, P\* = the
     smallest P on a 0.01 grid at which that set's control fraction with P ≥ P\* is ≤ the forward S15 production
     control fraction with P ≥ 0.75 (from `refine/conf/P_by_candidate.parquet`, all days).
  3. The same check is reported for B2, B3, B4 and the era detector (flagged the same way if clearly above).

### The ONE pre-registered truth look (per year)
- `bw_p6_onelook.py` writes `ONELOOK_OPENED.json` FIRST (time UTC and PT, sha256 of `models/bw_models.joblib` and of
  the forward models), refuses to run if it exists, and refuses if the model hash differs from `MODELS_FROZEN_BW.json`.
  Nothing is fitted, tuned or re-thresholded on what it reads.
- Days = the Bostock window days of `truth_episodes.csv`: **2003** (02-26 → 03-10), **2005** (09-03 → 09-25), **2007**
  (01-24 → 02-03), **2008** (05-10 → 06-02), **2009** (05-10 → 06-07); all 2-h blocks. Events = `bostock_all()` on those
  days.
- Detector × set scored: frozen B0 (2003), frozen B1 (2005), frozen B2 (2007), frozen B3 (2008, 2009); era (2003, 2005).
  Reported beside, marked **already seen**: 2004 (02 → 27 Jul) TEST blocks for frozen B0 and era (seen in G3; the era
  build blocks are its fit rows and are not scored).
- Per row: n events; **recall** = one-to-one, own family, ± 2 s (`svi_ref_common.one2one_recall`) by the data
  candidates with **P ≥ 0.75**; **precision** = fraction of those candidates within ± 2 s of an event of the same family;
  the same two at the set's T_core (frozen 8.75; CN4/B1 at both bracket ends; era 8.25) for comparison with G1/G3;
  AUC(P_same) and AUC(net_mad) for `m_same`; calibration slope (forward `calib`); matched/ΣP; control P > 0.5
  fraction on the same days; families rediscovered (≥ 5 matched at P ≥ 0.75); **his/ΣP-excess** = his events /
  (ΣP_same data − ΣP_same control) over the window (the SCOPE §5 k check, against the forward 4.4–4.7 and the set's
  own fit-day value).
- Bars, SCOPE §5 as written: slope 0.8–1.2; matched/ΣP 0.8–1.2; control P > 0.5 ≤ 1 %. G5: an era/set failing a bar
  is reported as a ΣP bracket only (P7 rates use ΣP excess everywhere anyway). Recall is read against the 2010–2013
  band 0.12–0.21 (no bar).
- Data-candidate counts per window and the scrambled-control counts at P ≥ 0.75 are reported too.
